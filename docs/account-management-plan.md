# 账号管理移植方案

关联 [Issue #9](https://github.com/0xHanniba1/jt_idea_notes/issues/9)。

## 已确认范围

按 jt_crm 的左创建表单、右账号卡片布局和账号操作移植；保留想法簿现有 Go、React、SCSS、Lingui、角色和权限。用户名用于登录且不可改，昵称用于显示且可自行修改。用户名、账号 ID、密码和业务关联沿用现有数据，无需迁移表结构。

## 实施

- 创建账号表单常驻，包含用户名、昵称、角色、可选临时密码。用户名仍为 3–32 位并统一小写；按最新确认，手填密码为 8–12 个 Unicode 字符。
- 空临时密码由 Go crypto/rand 生成。仅在事务提交成功的响应中一次性返回，不存明文、不记日志、不持久化到浏览器。成功交接弹窗关闭后清空。初始化、重置、恢复沿用相同语义。
- 账号卡片展示昵称、@用户名、角色、状态及操作。搜索、状态筛选和分页由后端查询和计数统一处理；保持角色筛选及历史账号初始化能力。
- 个人设置用户名只读，服务端收到 username 字段明确拒绝；昵称 trim 后最多 100 Unicode 字符。修正此前创建 100 字节与个人设置 50 字节的不一致。
- 保留普通成员禁止管理、最后有效管理员保护、自我停用/降级保护、重置/停用会话撤销及恢复需新临时密码的约束。

## 诊断与验证边界

现有隔离版本已实际调用管理员创建接口成功；未复现用户所说的失败。已排除空邮箱唯一索引和用户序列漂移；昵称字节数与 UI 字符数限制不一致已确认。本轮通过新的完整创建链路、清晰错误和交接界面解决使用阻碍，不虚构旧失败根因。

使用独立账号管理验收数据库、4184 端口和 JWT 密钥，测试账号不写入本机 4180 或云端。覆盖创建、重复用户名、中文昵称边界、首登改密、昵称不改变用户名、角色、重置、启停及普通成员限制；检查桌面/窄屏和深浅主题。

用户验收前不合并 main、不发布云端，不修改真实密码。验证结果如下。

## 密码长度调整（2026-09-17）

按用户最新要求，创建、初始化、重置、恢复、首次改密和个人改密统一为 8–12 个 Unicode 字符，保留空格、中文和原有弱密码校验。服务端自动生成 12 位临时密码。已有较长密码保留原校验边界，可继续登录和作为改密时的当前密码使用；不会重置现有账号密码。

本次调整已通过 `make test`（Go race/short、24 套件/225 项前端测试）、`make lint`、构建和实际 HTTP 边界验证：7/13 位拒绝，8/12 位可创建、首次改密、个人改密和重置；旧长密码仍可登录。4184 页面已显示新提示，4180 和云端未变更。
