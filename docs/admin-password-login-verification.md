## 环境与数据边界

- 独立预览：`http://jt-idea-notes.localhost:4182/`；本机 development 模式允许 localhost HTTP。生产配置必须使用 HTTPS。
- 独立开发库 `jt_idea_auth_dev`，从原隔离开发库复制后追加迁移；自动化库 `jt_idea_auth_test`。二者均在本地开发数据库容器的 15566 端口，未连接 4180 数据库。
- CLI/恢复演练另用 `jt_idea_auth_bootstrap`、`jt_idea_auth_restore`。未启动这两个库的 Web 实例。
- 配置与测试账号材料在忽略目录 `tmp/password-auth/`；环境文件权限 0600，使用独立 JWT secret。邮件仅进入开发 Mailpit，不发送真实邀请或密码邮件。
- 迁移后、验收新增记录前，比较 7 组原始行的 SHA-256：39 条记录、17 条评论、44 条关注、8 条附件、4 个标签、2 个标签关系，以及 3 位原用户的 ID、姓名、邮箱、角色、状态和头像等资料全部一致。认证 stamp/API Key 不作为业务资料摘要字段。

## 验收发现并修复的问题

1. absolute-form HTTP 请求导致读取上限匹配到错误路径：改为与路由一致的 URL path/query，并补普通/分块请求回归。
2. 业务认证的租户排他锁与 SQL 附件的独立事务外键锁互相等待：改为 `FOR NO KEY UPDATE`，保留认证撤销的互斥语义，同时允许外键检查。
3. Cookie 仅限站点主机后，私有图片不能继续指向公共 CDN：前后端图片 URL 使用站点同源；头像、图片和导出响应不公开缓存。
4. 原客户端通用错误可能回传请求体：网络错误不再包含请求 body，避免密码进入错误上报。
5. 隐藏的 GET 写入路径（读取通知、验证联系邮箱、测试 Webhook）补认证锁；数据库错误没有写响应时返回失败，不再留下空成功响应。
6. 保留原 RSS 配置数据，但新内部站点不再展示公开订阅入口；旧登录配置界面和 API Key 界面移除。错误登录使用中文表单提示，不再额外叠加英文通用提示。
